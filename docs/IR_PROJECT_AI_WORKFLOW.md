# IR Project AI — единый конвейер обработки листов КМ / КМД

**Статус:** разработка в `feature/ir-project-ai-next`, после предыдущего этапа 3D-точек. По просьбе пользователя на текущем этапе **не выполняются** скачивание моделей и зависимостей, npm install, тесты, сборка Electron, Windows-релиз и перенос в `main`.

## Цель

Объединить ранее реализованные модули IR Project AI в понятный маршрут:

1. Загруженный оригинальный PDF КМ/КМД внутри объекта (контрольная сумма SHA-256).
2. Индексация реальных листов PDF (текстовый слой, без претензии на OCR).
3. **Очередь выбранных листов** для последовательного локального визуального анализа.
4. Реальный результат локальной модели со ссылкой на исходный документ, лист и SHA-256.
5. **Обязательная проверка инженером** в существующем `ai-review`; оригинальный ответ модели `raw` не переписывается.
6. Указание точного количества марок по спецификации, проверка металла, крепежа, сопоставление КМ/КМД и размещение 3D в ранее созданных отдельных модулях.

Переходы между этапами **не означают автоматической записи** извлечённых марок/масс/количеств в основные таблицы проекта. Нейросеть пока распознаёт только явно видимые надписи и обозначения, а не готовую проверенную деталировку.

## Очередь PDF

Новый модуль `src/ai-workflow.js` с местным SQLite-хранилищем через существующий `object_records`:
- `ai-workflow-tasks` — задание для одного листа;
- `ai-workflow-events` — хронология статусов и ошибок.

Для листа храним `documentId`, имя, тип КМ/КМД, SHA-256, номер страницы, ID текстового индекса, ID сохранённого анализа, число попыток и причину сбоя.

Добавлять можно только **реальные листы из индекса PDF, у которого SHA-256 соответствует текущему загруженному оригиналу**. Для документа 1–80 листов за одно добавление. Действующие дубли того же `documentId + SHA-256 + page` не добавляются. Для предупреждения неограниченного роста данных действуют ограничения истории очереди: не более 500 заданий на объект; старые подтверждения и анализы автоматически не удаляются.

**Статусы**: в очереди, распознаётся, прервано, нужна модель, ожидает инженера, подтверждено, отклонено, ошибка, источник изменён, отменено. Статусы **«Подтверждено / Отклонено»** выводятся из существующей записи `ai-review`, а не вводятся очередью самостоятельно.

## Выполнение

- Обработка начинается **только по нажатию инженера** «Запустить очередь». Система не запускается при старте Windows или IR Project и не подключается к интернету.
- В пределах объекта работает один процесс очереди, листы последовательно вызывают существующий локальный `aiResults.analyzePdf()` (без второго кода распознавания).
- Перед каждым листом проверяем доступность исходника (по документу/контрольной сумме) и готовность движка.
- Если модель не установлена/не запущена — текущий лист получает статус «Нужна модель», обработка останавливается, результаты не имитируются.
- «После текущего листа» ставит флаг остановки. Уже выполняющееся распознавание не прерывается посередине; следующий лист не стартует.
- Ошибка текущего листа записывается в историю, другие выбранные листы остаются доступны. При повторной попытке система сначала проверяет наличие уже сохранённого анализа с той же тройкой `documentId + SHA-256 + page`, чтобы не генерировать второй ответ, если приложение прервалось между сохранением анализа и обновлением очереди.
- После повторного запуска приложения незавершённое `running` визуально считается прерванным; его нужно вручную повторить.
- Если PDF удалён или заменён, старая запись видна как «Источник изменён», но не запускается на новом файле. Для новой ревизии нужно проиндексировать её и заново выбрать листы.
- Результат попадает **только в локальный журнал `ai-analysis` и затем в `ai-review`**; не происходит автопереноса в `marks`, `materials`, схему или готовность проекта.

## Полномочия

Просмотр очереди доступен в рамках доступа к объекту. Добавление, запуск, повтор, остановка и отмена требуют роли инженера/администратора и подтверждённой IPC-сессии проверки пароля. Пользовательские кнопки на странице — не единственная защита. Доступа к производственным разделам модуль не получает.

База SQLite **не мигрирует** и существующие записи не перезаписываются; в `object_records` добавляются только новые `section_key`. Операции записи статуса и события исполняются одной транзакцией.

## Интерфейс

Новая вкладка **«Конвейер ИИ»** содержит:

- последовательность 5 блоков: чертежи, очередь, инженерная проверка, ведомости, сравнение/3D;
- переход к каждому ранее реализованному разделу IR Project AI;
- выбор конкретного **проиндексированного** PDF и галочки по листам;
- кнопки добавить выбранные, запустить очередь, остановить после листа, повторить ошибку, отменить невыполненное, открыть историю;
- живые обновления статусов через Electron IPC, без перезапуска страницы;
- честные числовые итоги по существующим записям и предупреждение о неполной сверке.

Отсутствие модели не мешает загрузить PDF, индексировать его, подготовить очередь и вручную заполнить инженерные данные по чертежам. Для настоящего автоматического распознавания потребуется установленная и проверенная локальная модель.

## Что остаётся до завершения IR Project AI

1. Сквозной процесс **структурированных предложений** из OCR/VLM по каждой позиции: количество экземпляров по спецификациям, профили, детали, соединения, координаты и материалы. Текущая модель `aiResults.analyzePdf` запрашивает только надписи/марки, поэтому полноценная автодеталировка ещё не реализована.
2. Инженерная проверка этих **типизированных предложений** перед записью в изолированные ведомости.
3. Управление комплектами/ревизиями КМ/КМД, чтобы отдельные корректные PDF не считались автоматически актуальными.
4. Общие проверки реальных чертежей, корректности SQLite/IPC/DOM и совместимости Windows-сборки — все ранее подготовленные контрактные тесты, а также интеграционные тесты очереди.
5. Выбор и установка офлайн-пакета PaddleOCR-VL/Qwen и производительные тесты на конкретной рабочей станции, **только после согласованной финальной интеграции**.
6. Общий релиз и Windows-установщик после успешной приёмки. Пока нет оснований объявлять процент готовности автоматически распознанной деталировки или выпускать «готовую версию».

**Важно:** на текущем этапе код сохранён в ветке, но не тестировался. Возможные ошибки будут устранены при общей проверке, как ранее попросил пользователь.
