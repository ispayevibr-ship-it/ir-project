# IR Project AI — этап проверки инженерных данных (черновик, после 1.7.217)

**Статус:** изменения сохраняются в отдельной ветке разработки. Пока не объединены с `main`, не включены в установщик Windows, не опубликованы через hot-update и не подвергались проверке, требующей скачивания зависимостей или весов. По просьбе пользователя общая проверка — после завершения следующих этапов.

## Новое

### 1. Проверка распознавания инженером

В `ИИ-распознавание → Проверка и ошибки` отображается запись каждого фактического анализа документа/листа/выделенной области. Отображаются первоначальные предложения ИИ, непонятные надписи, исходный файл и лист.

Инженер (либо администратор) может вручную исправить обозначения и присвоить статус:
- **Требует проверки** — предложение модели ещё не принимается.
- **Подтверждено** — марки вручную проверены по документу.
- **Отклонено** — предложение ИИ отклонено.

Сохраняются исходный ответ модели `raw`, оригинальные `extracted`, ссылка на PDF и координаты области. Они **не заменяются исправленными значениями**. Изменения пишутся в отдельное поле `review` и в `ai-review-history`; запись решения и журнала выполняется в единой SQLite-транзакции. Используется `expectedRevision` для отказа в перезаписи решения из другого окна без обновления.

### 2. Доступ и аудит

Просматривать материалы могут пользователи с доступом к объекту. В этом этапе операции подтверждения разрешены только после повторного ввода пароля инженера/администратора, проверяемого в **Electron IPC**, а не только JavaScript-кнопкой. Временная авторизация действует для конкретного окна до 10 минут.

Существующие общие роли IR Project и локальная база ещё не обеспечивают полноценную многопользовательскую синхронизацию и серверное разграничение доступа к объектам. Это не заменяет будущий переход на Supabase.

### 3. Реестр подтверждённых марок

В `ИИ-распознавание → Ведомость марок` выводятся только марки из записей со статусом **«Подтверждено»**. Для каждой марки показываются документы, номера листов, ссылки на области и число **подтверждённых упоминаний в анализах**.

**Категорически не следует путать:**
- Уникальные обозначения марок.
- Подтверждённые упоминания в разных анализах/листах.
- Количество фактических экземпляров отправочных элементов из спецификации (пока **не определено**).

Латинская `K41` и кириллическая `К41` преднамеренно не сливаются без проверки инженером. Удаление/отклонение подтверждения сразу исключает его из реестра.

**Основные ведомости марок IR Project не меняются автоматически.** Нет записи в `marks`, нет изменения количеств/масс и нет влияния на монтажную схему.

## Технические изменения

- `src/ai-review.js` — проверка, регистр, статусы, история, проверка источников и области объекта.
- `src/database.js` — синхронная SQLite-транзакция для решения/аудита без изменения схемы.
- `main.js`, `preload.js` — отдельный IPC для защищённой редакции.
- `src/ai-recognition-page.js`, `src/ai-recognition-page.css` — экран инженерной проверки и реестр марок.
- `scripts/test-ai-review.js` — контракты проверки, слияния марок, корректного повторного счёта, истории и изоляции объектов (предусмотрены для финального запуска).

## Ограничения текущего этапа

- Нет новых данных ИИ, если реальная локальная модель не установлена. Интерфейс работает только с фактически полученными результатами, без демонстрационных фиктивных чертежей.
- Нельзя утверждать количество элементов, массу, металлопрокат, метизы или геометрию из одного упоминания марки.
- Различия ревизий, точная ведомость отправочных марок и импорт подтверждённых данных в основные разделы — следующие этапы.
- Не меняются основные отчёты, существующая монтажная схема, учёт накладных и SQLite-схема.
- Проведение сквозных тестов, Windows-установщик и горячие обновления сознательно отложены до завершения следующих этапов.
