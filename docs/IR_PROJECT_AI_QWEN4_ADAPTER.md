# IR Project AI — этап II.3, версия 1.7.213: запуск Qwen3-VL 4B из менеджера моделей

## Реализовано

Менеджер подписанных моделей и движок распознавания теперь объединены:
1. Если через менеджер моделей установлена **Qwen3-VL 4B**, локальный AI Engine видит активную версию.
2. Перед запуском файлов запуска выполняется полная повторная проверка Ed25519-подписи манифеста и SHA-256 всех файлов установленной версии.
3. При ошибке проверки, отсутствующих файлах или несовместимом пакете запуск блокируется.
4. Для реального llama.cpp процесс запускается из проверенной папки `bin`, обращается только к `127.0.0.1` и использует случайный API-ключ. Режим CUDA / число offload-слоёв берётся только из подписанного поля `runtime.gpuLayers`; по умолчанию 0 (CPU). Нет недостоверного автоматического GPU-ускорения.
5. Статус ИИ показывает фактически выбранные модель и версию. История анализа изображений и PDF сохраняет идентификатор и версию модели, выполнившей запрос.
6. В разделе **«Настройки → Локальные ИИ-модели»** для установленной Qwen3-VL 4B добавлена кнопка «Проверить файлы». В отличие от собственно запуска, она проверяет подпись и SHA без запуска нейросети.
7. При отсутствии установленной 4B прежняя локальная схема работы с отдельно настроенной 8B сохранена для совместимости.
8. Установка или откат модели блокируются при работающем ИИ.

## Формат подписанного runtime в .ir-ai-pack

Для Qwen3-VL 4B должен быть подписан не только список хэшей, но и объект `runtime` в `manifest.json`:

```json
{
  "schema": 1,
  "modelId": "qwen3-vl-4b",
  "version": "1.0.0",
  "engine": "llama.cpp",
  "keyId": "ir-project-publisher-2026",
  "minAppVersion": "1.7.213",
  "runtime": {
    "binary": "bin/llama-server.exe",
    "model": "model/model.gguf",
    "vision": "model/mmproj.gguf",
    "gpuLayers": 0
  },
  "files": [
    {"path":"bin/llama-server.exe","bytes":123,"sha256":"<настоящая sha256>"},
    {"path":"model/model.gguf","bytes":456,"sha256":"<настоящая sha256>"},
    {"path":"model/mmproj.gguf","bytes":789,"sha256":"<настоящая sha256>"}
  ]
}
```

В ZIP должны присутствовать `manifest.json`, `manifest.sig` (Ed25519) и перечисленные файлы в `files/...`, а также все необходимые для запуска Windows-библиотеки DLL как дополнительные подписанные файлы. **Цифры и хэши выше условные**. Linux-тесты используют `bin/llama-server` вместо `.exe` и проверяют код с тестовыми байтами, не настоящими весами.

## Что пока не сделано

- **Настоящие веса Qwen3-VL 4B и исполняемый Windows/CUDA llama.cpp пока не публикуются в качестве официального пакета**. Пустой набор доверенных ключей означает, что IR Project 1.7.213 не сможет установить непроверенный пакет без утверждённого издателя.
- Нет доказанного запуска настоящей Qwen3-VL 4B на NVIDIA RTX 4050 Laptop / 6 ГБ VRAM / 16 ГБ RAM. Тесты CI используют имитацию локального процесса и HTTP-ответов, зато реальную криптографическую проверку подписанных тестовых файлов.
- Официальный совместимый билд llama.cpp, набор CUDA DLL, соответствующая GGUF-модель и mmproj должны быть закреплены по точным версиям и проверены на реальном ПК, прежде чем предоставлять скачивание.
- Интеграция PaddleOCR-VL 1.6 — следующий этап; она остаётся отдельным адаптером и не считается подключённой.
- Проверка SHA при запуске больших моделей может занимать значительное время: позже нужен безопасный кэш проверок без снижения доверия.
- Для оптимального использования RTX 4050 GPU offload и разрешение изображений должны подбираться на реальных измерениях использования VRAM; сейчас профиль по умолчанию — CPU.
- Резервный архив SQLite не включает оригиналы AI-чертежей.

## Проверки приемки

- Установка поддельного пакета без корректной подписи блокируется.
- Подписанная неполная сборка модели не считается готовой к запуску.
- Реальная идентичность модели и версия сохраняются в данных анализа.
- При повреждении модели запуск невозможен; при откате активная версия меняется только после проверки.
- Сохранена совместимость прежнего режима Qwen3-VL 8B и штатных функций IR Project.
