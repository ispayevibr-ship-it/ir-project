# IR Project AI — первый реальный тест Windows

Статус: подготовка. Ни один шаг этой инструкции не выполняется автоматически.

## 1. Изолированная тестовая сборка
В GitHub Actions вручную выберите workflow **IR Project AI Windows Preview**,
ветку `feature/ir-project-ai-next` и введите `PREVIEW`.
Только после отдельного разрешения на сборку запускайте workflow.
Он не публикует Release и не обновляет `main`. Установщик не содержит весов моделей.
Проверьте скачанный artifact перед запуском на тестовом ПК.

## 2. Ключ издателя
На доверенном офлайн-компьютере создайте защищённый каталог ВНЕ репозитория,
затем выполните:
```powershell
node scripts/ai-publisher-keygen.js D:\IR-AI-PRIVATE ir-project-ai-2026
```
Сверьте SHA-256 SPKI fingerprint через независимый доверенный канал.
Никогда не передавайте private.pem в GitHub, CI, чат или установщик.
После утверждения добавьте ТОЛЬКО содержимое public.pem и его fingerprint
в `src/ai-trusted-publishers.json` (schema=1, publishers:
[{keyId,publicKeyPem,sha256Spki}]).
Создайте отдельный коммит в feature-ветке. Пересоберите preview по отдельной команде.
Ключ не генерируется в CI и не загружается из сети.

## 3. Подготовка моделей (только после отдельного разрешения)
Получите лицензированные исходные веса и Windows runtime из проверенных
источников. Зафиксируйте версии, SHA-256 и происхождение каждого файла.
Qwen требует GGUF, mmproj GGUF, llama-server.exe и DLL.
PaddleOCR требует paddleocr-worker.exe, layout и VL weights с полными pin-файлами.
Существующие команды:
`node scripts/build-qwen4-pack.js --...`
`node scripts/build-paddleocr-pack.js --...`
Обе команды принимают локальные файлы, не скачивают модели и подписывают
пакеты закрытым ключом. Закрытый ключ остаётся на доверенном ПК.
Перед установкой сверяйте modelId, версию, подпись и SHA-256.

## 4. Проверка на Windows
Используйте отдельный тестовый профиль/ПК и резервную копию проекта.
Установите оба подписанных .ir-ai-pack через настройки «Локальные ИИ-модели».
Нажмите «Проверить готовность к КМД», затем по разрешению запустите движок
и распознавание. Проверка готовности сама по себе не доказывает точность.

## 5. Приёмка по реальному комплекту КМД
Зафиксируйте для каждого листа: номер, ревизию, марки, количество экземпляров,
детали, метизы (болты, гайки, шайбы), массы, соединения, источник/координаты,
уверенность и необходимость инженерного подтверждения.
Сравните с исходным PDF и контрольной ведомостью; не заменяйте
неоднозначные результаты догадками. Ошибки распознавания, отсутствующие
марки и расхождения массы фиксируйте отдельно. Проверяйте связь с 3D
только после подтверждения инженером.

## Запреты до разрешения
Не запускать тесты, не скачивать модели, не запускать GitHub Actions preview,
не собирать установщик, не публиковать Release, не изменять main.
Пароли существующих пользователей не менять.
