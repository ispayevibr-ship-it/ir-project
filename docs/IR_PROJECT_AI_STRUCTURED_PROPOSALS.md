# IR Project AI — структурированные предложения из локального распознавания КМД

**Статус:** доработки только в ветке `feature/ir-project-ai-next`. По просьбе пользователя промежуточные тесты, скачивание нейросетей/зависимостей и Windows-сборка **не запускаются**. В `main`, существующие документы и производственную базу изменения не вносятся.

## 1. Назначение

Связать ранее реализованный конвейер листов PDF с **типизированными предложениями** модели и отделённой от него инженерной проверкой. Пока модель способна предполагать лишь текст/значения, которые ей видны. Она **не является** источником утверждённой спецификации и не способна автоматически гарантировать точность КМД.

Каждая позиция относится к конкретному анализу, `documentId`, SHA-256 оригинального PDF, листу и фрагменту (если указано в анализе). Цитата `evidence.quote` и место `evidence.location` — **заявления модели**, которые инженер должен сверить с первоисточником; это не независимая OCR-верификация координат.

## 2. Типы предложений (`ir-kmd-v1`)

Новый строгий JSON-контракт принимает массив `records`, максимум 80 позиций за один ответ:

| Тип | Назначение | Основные поля |
|---|---|---|
| `mark_quantity` | Количество конкретной отправочной марки из спецификации | `mark`, `cipher`, `secondaryCipher`, `specPosition`, `quantity` (целые шт.) |
| `steel_part` | Отдельная деталь отправочной марки | `mark`, `position`, `partType`, `partCount`, `profile`, `steelGrade`, `lengthMm`, `widthMm`, `thicknessMm`, `unitMassKg` |
| `connection` | Позиция соединения, метиза или шва | `mark`, `jointCode`, `fastenerKind`, `diameterMm`, `perJoint`, `standard` |
| `dimension` | Встречающийся размер по листу | `mark`, `position`, `lengthMm`, `widthMm`, `thicknessMm`, `diameterMm` |

Для любого типа нужны `type`, буквальное видимое обозначение `mark` и `evidence.quote`. Необязательные числа, которые невозможно однозначно прочитать, остаются `null`. Никакого заполнения по умолчанию из массы, числа упоминаний, нормы плотности или внешнего вида рисунка.

**Числовые правила:** строго положительные величины в ожидаемых единицах, без перевода из неустановленной системы. Количество отправочных марок — строго целые штуки. Отсутствующий номер спецификации или марка стали помечается предупреждением, а не достраивается автоматически.

Старый формат `{text,marks,notes,unknowns}` сохраняется для совместимости с существующим журналом. Анализы старого формата **не получают искусственные структурированные позиции**: у них просто отсутствуют `records`.

## 3. Исходный ответ и инженерная проверка

`src/ai-analysis.js` теперь отправляет локальной модели уточнённый запрос с форматом `ir-kmd-v1`. В `ai-analysis` сохраняется **оригинальный ответ модели без изменений**; структурные данные извлекаются в отдельные объекты `extracted.structured` и могут быть повторно прочитаны из `raw`. Никакое новое задание очереди не создаёт подтверждённую запись автоматически.

Модуль `src/ai-structured-review.js` связывает позиции по `analysisId + candidateIndex` и fingerprint нормализованной первоначальной записи. Редактирование проверенного значения/решения не перезаписывает оригинал. В существующей таблице `object_records` появляются новые разделы:

- `ai-structured-reviews` — отдельное решение инженера для конкретной позиции;
- `ai-structured-review-history` — история редакций с предыдущими и новыми исправлениями.

На стороне Electron IPC поддерживается сохранение только для инженера или администратора с повторно проверенным паролем. При редактировании проверяется `expectedRevision`. Изменившийся или отсутствующий исходный PDF лишает прежние решения статуса действующих; старая SHA и история остаются в аудите.

Состояния: **Требует проверки / Проверено инженером / Отклонено**. Если модель отметила неопределённость, подтверждение требует комментария о сверке исходного чертежа. Подтверждение неподтверждённого количества или отсутствующей позиции детали отклоняется.

## 4. Интерфейс

Добавлена самостоятельная вкладка **«Предложения ИИ»**, связанная с этапом проверки конвейера. Она показывает:

- тип предложения, исходный PDF/лист/хеш, цитату и указанное моделью место на чертеже;
- распознанные значения и предупреждения о пропусках;
- переход к просмотру исходного PDF;
- форму индивидуальной проверки, исправление отдельных числовых/текстовых полей, статус и комментарий;
- журнал решений и блокировку подтверждения при проблемах с источником.

**Для `mark_quantity`** после сохранённого инженерного подтверждения у PDF КМД доступна кнопка **«Подготовить в ведомость»**. Она открывает ранее существующую форму отправочных марок, предварительно заполняя проверенные `mark`, `cipher`, `quantity`, `specPosition`, `drawingRevision` и исходный документ/лист. Форма открывается **как новая запись со статусом «Требует проверки»**: инженер может внести исправления и отдельно сохранить её с проверкой пароля. Существующие ограничения на дубли, ревизии и количество марок не меняются. Если позиция уже существует в ведомости, сохранение новой записи будет отклонено; потребуется исправить исходную позицию.

По остальным типам `steel_part`, `connection`, `dimension` подтверждённые данные пока остаются в отдельном реестре предложений. Прямой перенос в соответствующие ведомости и 3D потребует дополнительных мапперов с полной валидацией, которых в этом этапе нет. Это исключает создание фиктивной геометрии или массы.

## 5. Новые и изменённые файлы

- `src/ai-structured-extraction.js` — JSON-схема `ir-kmd-v1`, безопасный разбор, контроль размерности, пропусков и происхождения.
- `src/ai-structured-review.js` — отдельные инженерные решения, источник, история, ревизии и роли.
- `src/ai-proposals-page.js`, `src/ai-proposals-page.css` — индивидуальная проверка, редактирование, просмотр источника.
- `src/ai-analysis.js` — запрос структурированного ответа у локальной модели, запись исходного ответа и `extracted.structured`.
- `src/ai-recognition-page.js` — вкладка и подготовка подтверждённого количества для текущего редактора.
- `src/ai-workflow-page.js` — переход из конвейера к предложениям.
- `src/index.html` — подключение интерфейса.
- `main.js`, `preload.js` — изолированный IPC доступа к предложениям.
- `scripts/test-ai-structured-proposals.js` — подготовленный, **не запущенный** контракт для финальной проверки.

## 6. Ограничения

- Конкретные результаты OCR/PaddleOCR-VL и Qwen3-VL на настоящих спецификациях КМД **ещё не проверены**. Формат может потребовать адаптации промпта, обработки неточного JSON и разбивки таблиц на фрагменты.
- Источник цитаты в JSON предоставляется самой моделью, а не строгим сопоставлением текста с конкретными PDF-координатами. Проверка на исходном листе обязательна.
- Общее число отправочных элементов не вычисляется по числу упоминаний, а подтверждается по спецификациям.
- Не реализовано автоматическое создание готовых 3D-координат, сварных тел, отверстий и сложных деталей из ответа модели.
- Не реализована проверка актуальной ревизии **всего комплекта** КМ/КМД.
- Промежуточное тестирование логики SQLite, интерфейса Electron, синтаксиса и Windows-компонентов отложено по просьбе пользователя. Код в ветке считается непроверенным до финальной приёмки.

## Следующий этап

Подготовить **управление ревизиями комплектов КМ/КМД**, а затем безопасную поштучную маршрутизацию подтверждённых деталей/узлов в изолированные ведомости и пройти единую приёмку с локальными моделями и реальными листами КМД.
