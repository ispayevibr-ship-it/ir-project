# IR Project AI — этап 3 (1.7.209): проверяемый текстовый индекс PDF

## Реальные возможности

- Импортированный PDF (до 48 МиБ; максимум 80 страниц на этом этапе) читается **локально**.
- Индексация запускается вручную через «Чертежи КМ/КМД → Индексировать PDF».
- Используется PDF.js (pdfjs-dist 6.4.299, Apache-2.0), **не облачный ИИ**.
- Обработка выполняется отдельным Node worker_threads с лимитом памяти и тайм-аутом.
- Из каждого листа извлекаются страница, размеры, поворот, фрагменты текста и положения фрагментов в системе PDF (points), когда PDF содержит доступный текстовый слой.
- Связь индекса с номером документа и SHA-256 исходного файла обязательна. Сохраняется источник, а не произвольная модельная маркировка.
- Если значимого текста нет, лист получает статус «Текстовый слой отсутствует — нужен OCR».
- Для подозрительной кодировки отображается отдельное предупреждение.
- Индексы сохраняются в отдельной секции ai-pdf-index существующей SQLite для конкретного объекта. Миграция схемы БД не требуется.
- Повторная индексация того же неизменённого файла возвращает сохранённый результат, не дублируя данные.
- Исходный PDF не изменяется. Существующая монтажная схема/ведомости не затрагиваются.

## Ограничения

**Это не распознавание геометрии КМД, деталей, метизов или графических обозначений.** PDF с растровыми страницами, испорченными текстовыми слоями и векторными объектами без текста пока нужно обрабатывать следующим визуальным этапом. Текстовые координаты здесь в points из PDF; они ещё не являются строительными размерами в миллиметрах. Система не выводит марки, количество, массу или размеры конструкций без проверки.

Использование стороннего PDF.js и реальных Node worker на Windows в Electron требует практического тестирования в установленной программе. CI запускает локальный PDF.js на сгенерированном тестовом PDF, включая проверку текстового слоя и пустой страницы. UI скриншоты/отображение в Electron ещё не проверены.

Ограничения первой реализации: 48 МиБ на PDF; 80 листов; не более 1000 текстовых фрагментов и 24000 символов на лист. На больших листах выводится признак сокращения индекса. Для более крупных комплектов потребуется пакетная обработка/возобновление и более строгая изоляция парсера.

Модуль пока не включает бинарные файлы Qwen3-VL-8B-Instruct и llama.cpp, официальный офлайн-пакет модели ещё не выпускается. Процесс безопасного распространения и проверки подписей остаётся отдельной задачей. SHA-256 внутри произвольного manifest **не заменяет цифровую подпись доверенного пакета**.

## Техническая структура

- src/ai-document-store.js: разрешение/валидация конкретного сохранённого документа по объекту + контроль SHA-256.
- src/ai-pdf-worker.js: parse PDF.js через getDocument/getPage/getTextContent.
- src/ai-pdf-index.js: отдельный worker, хранение индекса по объекту, повторное использование сохранённых результатов.
- main.js / preload.js: ai-pdf:index, ai-pdf:list, ai-pdf:page через Electron IPC.
- src/ai-recognition-page.js/css: кнопка PDF, список листов, статусы и просмотр текста.
- scripts/test-ai-pdf.js: проверка **реально сформированного PDF**, включая текст K41 и пустой лист.
