# IR Project AI — этап 2 (1.7.208)

## Что действительно реализовано

Нативный движок src/ai-local-engine.js проверяет **три файла локального пакета** (исполняемый файл llama-server, языковая GGUF-модель Qwen3-VL-8B-Instruct и vision-проектор mmproj), проверяет контрольные суммы SHA-256, объём RAM, запускает отдельный процесс на 127.0.0.1 со случайным портом и случайным API-ключом. Статус «Готова» показывается только после успешного HTTP health-check. Остановка завершает дочерний процесс. Никакие запросы к облачному ИИ не выполняются. Интерфейс не запускает модель без проверенного локального комплекта файлов.

При реально запущенной модели кнопка «Распознать» доступна для PNG/JPG до 16 МиБ. src/ai-document-store.js проверяет SHA-256 загруженного источника и сигнатуру PNG/JPEG. src/ai-analysis.js отправляет байты через localhost в модель, сохраняет её исходный ответ, извлечённые поля и SHA-256 источника в объектной секции ai-analysis SQLite. **Это непроверенная гипотеза нейросети, а не утверждённые данные КМД**. На вкладке «Проверка и ошибки» есть исходный ответ и связь с документом; геометрия источника и координаты найденных фрагментов пока отсутствуют.

## Что пока НЕ сделано

- **Не включены веса, библиотека и Windows llama-server**; готовый подписанный офлайн-пакет ещё не опубликован. Без него модель в программе не запустится. Обычный 1.7.208 установщик содержит только инфраструктуру.
- Не подтверждена работоспособность конкретного Qwen3-VL GGUF и Windows llama-server на реальном компьютере; тесты исполняют HTTP-макет с соблюдением фактического формата API, НЕ настоящую нейросеть.
- PDF, TIFF, DXF, DWG сохраняются, но не анализируются. Для PDF нужен защищённый рендеринг в страницы с масштабом и привязкой к исходному листу.
- Нет точного поиска координат символов, размерных линий, деталей и узлов. Нельзя переводить результат в ведомость или монтажную схему без отдельной инженерной проверки.
- GPU определяется по manifest.gpuLayers, а не автоматически; CPU fallback gpuLayers=0. Минимальная проверка ОЗУ 8 ГБ, рекомендуемая конфигурация будет установлена только после реального теста.
- Авторизация нового AI IPC пока наследует ограничения общей системы ролей, которые недостаточно жёстко проверяются на стороне Electron. До многопользовательского доступа нужно добавить нативные сессии.
- Комплексная резервная копия с вложениями ИИ ещё не реализована.
- **Контрольные суммы manifest.json не являются цифровой подписью поставщика.** Нельзя запускать пакеты из неизвестных источников. Перед официальным распространением необходимо добавить pinned signature и проверять комплектность DLL.

## Формат будущего официального офлайн-пакета

Каталог на компьютере пользователя: userData/ir-project-ai/runtime/

Обязательные файлы:
- llama-server.exe (Windows, совместимая версия llama.cpp, плюс его DLL)
- model.gguf (Qwen3-VL-8B-Instruct Q4_K_M)
- mmproj.gguf (согласованный визуальный энкодер)
- manifest.json

manifest.json:

```json
{"format":1,"engine":"llama.cpp","modelId":"Qwen3-VL-8B-Instruct",
 "gpuLayers":0,
 "sha256":{"binary":"<sha256 llama-server.exe>",
 "model":"<sha256 model.gguf>","vision":"<sha256 mmproj.gguf>"}}
```

Хэши в примере — **не реальные**. Разработчик официального пакета обязан вычислить их по фактическим бинарным файлам, проверить их происхождение, согласовать лицензии и подписать пакет. Не следует ставить случайные llama-server.exe из интернета: приложение запускает этот файл.

Официальная модель: https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct-GGUF
Документация multimodal llama.cpp: https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md
