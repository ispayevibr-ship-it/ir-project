# База знаний IR Project

Всё, что уже известно о чертежах, — чтобы не читать один и тот же комплект дважды и не тратить запросы к Claude.
Папка приезжает в программу вместе с горячим обновлением (каждый файл перечислен в `hot/latest.json`).

## Что здесь лежит

| Путь | Что | Кто пользуется |
|---|---|---|
| `sets/<id>.json` | разобранный комплект: файлы (SHA-256), резервуар, элементы, сетка, марки | шаг «Анализ»: совпали все файлы записи — шаг Claude заполняется отсюда, без запроса |
| `rules.json` | правила «марка / буквы → вид конструкции» (ключи из `src/ai-structure-types.js`) | расстановка (после правил инженера) и запрос к Claude |
| `global/*.json` | общая инженерная база: виды, сортаменты, нормативы, правила, источники (см. `global/README.md`) | все объекты; `src/ai-global-kb.js` |
| `global/templates.json` | уровень Б: шаблоны изображения на чертежах — что изображено, признаки, правило кода и его тест (без значений объекта) | все объекты; проверка `scripts/test-ai-knowledge-levels.js` |
| `quality/*.json` (только в закрытом хранилище) | уровень Г: ошибки распознавания (`errors.json`), статистика способов чтения (`methods.json`), перепроверка комплектов (`recheck.json`, `history.json`) | страница распознавания «Качество способов чтения»; программа берёт их в `userData/knowledge-data/quality` |
| `projects/<шифр>.json` | особенности проекта: что значат буквы, отметки, сетка, что не сводится | человек и Claude в сессии разработки |
| `chat/link.json`, `chat/journal.json` | адрес чата программы с Claude; журнал исправлений по сообщениям инженеров | чат программы, страница «Журнал» |

Формат `sets/*.json` — как ответ Claude в `src/ai-montage.js` (без решений по схемам, они зависят от номеров листов):
`{id, title, project, files:[{name, sha256, kind}], source, created, result:{summary, marks, grid, elements, tank}, notes}`.
Комплект узнаётся по SHA-256 содержимого PDF — имя файла значения не имеет.

## Откуда пополняется

1. **Claude в программе.** После «Обработать через Claude» ответ сохраняется на компьютере в
   `%APPDATA%\ir-project\ai-learned\sets\` (тот же формат). Следующий анализ тех же файлов берёт его оттуда.
2. **Сессия разработки (Claude Code).** Забрать файлы из `ai-learned` с ПК пользователя, проверить по листам,
   исправить, положить в `knowledge/sets/`, добавить в `hot/latest.json`, выпустить горячее обновление.
   Общие выводы — в `rules.json` и `projects/`, а то, что годится для любых чертежей, — в правила кода
   (`src/ai-*-extract.js`) и в справочник `src/ai-structure-types.js`.

Запись из базы знаний важнее чтения листов (она проверена); свежий ответ Claude — дополнение к чтению листов.

## inbox/ — входящие с компьютеров

`inbox/<имя компьютера>/sets/*.json` — ответы Claude, полученные в программе; `inbox/<имя компьютера>/engineer.json` —
правила и заметки инженера. Присылает программа (Настройки → ИИ-помощник Claude → «База знаний на GitHub»).
Программа inbox не читает: записи проверяются в сессии разработки и переносятся в `sets/`, `rules.json`, `projects/`.
